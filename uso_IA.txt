Para desarrollar el **Paso 3**, vas a crear un componente llamado `Header.jsx` dentro de la carpeta `src/components/`. Su función es ofrecer un menú de navegación que cambie de página sin recargar la web.

Aquí tienes la explicación detallada y el código paso a paso:

### 1. Ubicación del archivo

Crea el archivo en la siguiente ruta:
`src/components/Header.jsx`

---

### 2. Puntos clave a tener en cuenta

* **Importar `NavLink`:** En React Router se utiliza `NavLink` (en lugar de etiquetas HTML `<a>`) para que la navegación sea SPA (Single Page Application) sin recargar la página. Además, `NavLink` detecta automáticamente qué ruta está activa para aplicar estilos CSS.
* **Propiedad `end` en el enlace de Inicio (`/`):** Por defecto, React Router verifica si la URL actual *comienza* con la ruta del `NavLink`. Como todas las rutas empiezan con `/` (por ejemplo, `/sobre-mi`), la ruta raíz `/` siempre se consideraría "activa". La propiedad `end` le indica a React Router que solo marque el enlace de **Inicio** como activo si la URL es **exactamente** `/`.

---

### 3. Código completo de `Header.jsx`

```jsx
import { NavLink } from 'react-router-dom';

export default function Header() {
  return (
    <header>
      <nav>
        <ul>
          <li>
            {/* Se agrega 'end' para que solo se active en la ruta exacta "/" */}
            <NavLink to="/" end>
              Inicio
            </NavLink>
          </li>
          <li>
            <NavLink to="/sobre-mi">
              Sobre mí
            </NavLink>
          </li>
          <li>
            <NavLink to="/habilidades">
              Habilidades
            </NavLink>
          </li>
          <li>
            <NavLink to="/proyectos">
              Proyectos
            </NavLink>
          </li>
          <li>
            <NavLink to="/contacto">
              Contacto
            </NavLink>
          </li>
        </ul>
      </nav>
    </header>
  );
}

```

---

### ¿Cómo funciona por dentro?

Cuando este componente se renderice en pantalla, `NavLink` le añadirá automáticamente la clase CSS `.active` al enlace de la página en la que te encuentres. Si deseas agregarle estilos CSS más adelante, podrás destacar el enlace activo simplemente apuntando a esa clase en tu archivo de estilos:

```css
/* Ejemplo de CSS */
nav a.active {
  font-weight: bold;
  color: #0070f3;
}

```

respuesta IA:
Ese problema ocurre porque en **PowerShell** el comando `tree` no ejecuta la herramienta habitual de ver archivos en consola, sino un alias interno o un comando de Windows que por defecto no filtra las carpetas del sistema (o porque intenta leer todo el directorio de OneDrive y llena la pantalla de carpetas ocultas).

Tienes **dos opciones** rápidas para solucionarlo:

---

### Opción 1: Usar `cmd /c tree /f` (La solución directa sin instalar nada)

Ejecuta esto directamente en tu terminal de PowerShell:

```powershell
cmd /c tree /f /a

```

* **/f**: Muestra tanto los archivos como las carpetas (si solo quieres ver carpetas, quita el `/f`).
* **/a**: Usa caracteres ASCII para que los guiones y líneas se vean bien formateados en la consola.

---

### Opción 2: Usar `tree` ignorando `node_modules` (Recomendado para React/Vite)

Si solo pones `tree`, la carpeta `node_modules` desplegará miles de archivos y congelará la terminal. Para ver únicamente tus archivos de código fuente, ejecuta:

```powershell
cmd /c tree src /f /a

```

*(Esto te mostrará solo el contenido limpio de la carpeta `src`).*

---

### Opción 3: Instalar `tree-node-cli` (La mejor alternativa para proyectos JS)

Si vas a usar seguido este comando en proyectos web, puedes instalar una herramienta ligera desde tu propia terminal:

1. Instálala globalmente con npm:
```powershell
npm install -g tree-node-cli

```


2. Úsala así en la raíz de tu proyecto:
```powershell
treee -I "node_modules|.git"

```



*(Nota las 3 "e": `treee`. Ignorará automáticamente las carpetas pesadas de Git y Node).*
